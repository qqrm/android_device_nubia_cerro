# Задание локальному агенту: консольный доступ и подготовка минимальной системы Cerro

Нужно довести до рабочего состояния управление домашним Nubia Z60 Ultra
**NX721J / PQ83A01 / cerro** из репозитория **qqrm/android_device_nubia_cerro**,
ветка **server-lite**. Схема уже реализована в `.github/workflows/deploy-phone.yml`:
GitHub Actions → Tailscale → обычный OpenSSH в Termux, порт **8022**.

**Актуальное направление:** подготовить консольный доступ по [CONSOLE.md](CONSOLE.md),
затем выполнить read-only `server/device/inventory.sh` для [минимального нативного
продукта](../HEADLESS.md). Termux — этап подготовки, а конечные SSH/inference-службы
должны запускаться без Android application framework. Если SSH-bootstrap уже прошёл,
используй существующие ключи и сначала проверь SSH через USB forwarding.
Не повторяй настройку браузерного входа Android-приложения Tailscale для консольного пути.
Если Android-приложение Tailscale уже работает, сохрани его до проверки нового маршрута.

Прочитай `AGENTS.md`, `server/termux/DEPLOY.md`, `server/termux/bootstrap-ssh.sh`
и `server/phone.py` в актуальной ветке. Выполни доступные действия самостоятельно,
не останавливайся на плане. Если нужны вход в аккаунт, подтверждение Android или
физическое подключение телефона, попроси только конкретное недостающее действие,
после него продолжи. Используй существующие авторизованные сессии и разрешённый доступ.

## Порядок работы

1. Найди checkout или клонируй репозиторий. Сохрани пользовательские изменения;
   не выполняй reset/clean поверх них. Установи, доступны ли `adb`, `ssh`, `gh`,
   виден ли нужный телефон и есть ли авторизация GitHub с правом настроить его environment.
   При нескольких телефонах явно выбери NX721J. Не публикуй device serial.

2. Проверь имеющуюся установку Termux и существующий SSH-bootstrap. Если Termux ещё нет,
   установи официальную версию; Termux:Boot должен иметь совместимый источник/подпись.
   Не настраивай Android VPN-приложение Tailscale: консольный вариант запускается после
   проверки SSH по USB. Не меняй сетевые настройки других устройств и не пробрасывай
   публичный порт на роутере.

3. Используй существующие deployment-ключ, SSH host key и доверенный bootstrap-вывод.
   Только если bootstrap ещё не выполнялся, создай отдельный Ed25519 deployment-ключ
   вне Git. Сохрани приватную часть локально с ограниченными правами; на телефон
   передай только `.pub`. В Termux установи `openssh python`, запусти
   `bootstrap-ssh.sh PUBLIC_KEY_FILE --wake-lock`.
   Используй терминал Termux/доступный пользовательский механизм: ADB shell без root
   не имеет права писать в private directory другого Android-приложения.
   Сохрани username и known_hosts-строку `cerro-phone ssh-ed25519 ...` из доверенного
   локального вывода. Проверь вход с `StrictHostKeyChecking=yes` и этим HostKeyAlias.
   Выполни `phone.py check` через USB forwarding по `CONSOLE.md`, затем установи
   закреплённый консольный Tailscale и проверь SSH по его адресу. Телефон и компьютер
   должны быть в одном tailnet. Одноразовый auth key телефона передавай приватным файлом;
   не путай его с OIDC identity GitHub runner. Существующий deployment-ключ не пересоздавай.

4. Настрой Tailscale grant и OIDC identity точно по `DEPLOY.md`. Сохрани существующую
   политику и права остальных устройств; учти, что allow-all перекрывает намерение
   ограничить CI одним телефоном. Identity должна быть привязана к этому repository ID,
   workflow, `server-lite`, environment `phone` и событию `workflow_dispatch`.
   Не сохраняй долгоживущий Tailscale auth key, если доступен настроенный OIDC.

5. Через локально авторизованный `gh` или GitHub UI создай environment `phone` с доступом
   только из branch `server-lite`. Запиши variables `PHONE_HOST`, `PHONE_USER`,
   `TS_CLIENT_ID`, `TS_AUDIENCE`; secrets `PHONE_SSH_KEY`, `PHONE_KNOWN_HOSTS`.
   Приватные ключи, API-ключи, JWT и токены передавай напрямую из файлов/памяти в secret store,
   не печатай их, не вставляй в отчёт, не коммить и не отправляй в чат.

6. Запусти и дождись завершения:

   ```sh
   gh workflow run deploy-phone.yml --ref server-lite --repo qqrm/android_device_nubia_cerro -f operation=check
   ```

   Найди ID именно созданного run и проследи его через `gh run watch`/`gh run view`.
   Исправь конкретные ошибки доступности, доверия host key или OIDC без отключения проверок.
   Если нужен patch в репозитории, делай отдельную ветку с проверками, а не обход политики.

7. Если пользователь уже выбрал и имеет локальную GGUF-модель, скопируй её по pinned SSH
   в `~/cerro-server/models/model.gguf` и запусти `operation=deploy`.
   Сначала останови старый ADB-сервер, если он занимает 8080. Не скачивай многогигабайтную
   модель и не выбирай её произвольно. Если модели пока нет, успешный `check` уже завершает
   настройку удалённого доступа; укажи, что inference-deployment ждёт модель.
   Проверь также прежний ручной запуск в Termux и `~/.termux/boot/10-cerro`: если они
   созданы по старой инструкции этого проекта, останови соответствующий процесс и
   отключи прежний boot helper с сохранением копии вне boot-каталога. Не убивай все
   процессы Termux и не удаляй неизвестные пользовательские boot-скрипты.

8. Проверь SSH с погашенным экраном. Настрой Termux:Boot и фоновую работу приложений.
   Самостоятельно телефон не перезагружай: если нужен reboot-тест, согласуй удобный момент.
   При разрешённом тесте отдельно проверь доступ до и после первой разблокировки.
   Автозапуск inference добавляй после успешного ручного deployment штатным launcher
   из `DEPLOY.md`, не создавай второй неуправляемый процесс `llama-server`.

9. Передай `server/device/inventory.sh` в `/data/local/tmp/cerro-inventory.sh` через
   авторизованный USB ADB и выполни `adb -s SERIAL shell sh /data/local/tmp/cerro-inventory.sh`.
   Сохрани вывод в приватный локальный файл вне checkout. При ненулевом exit code
   сохрани частичный отчёт и укажи недоступные разделы; не повышай права автоматически.
   По `server/HEADLESS.md` составь перечень зависимостей Wi-Fi, charging/thermal,
   power и storage для отдельного продукта без Zygote. На этой стадии ничего
   не отключай; подготовь конкретный обратимый набор изменений для следующего шага.

## Границы работы и результат

Не прошивай устройство, не разблокируй и не блокируй загрузчик, не делай factory reset,
не меняй SELinux и не удаляй пользовательские приложения/данные. Не выключай SSH host key
verification. При конфликте с уже настроенным SSH сначала установи, какой сервис используется.

Верни краткий отчёт: ссылка и итог GitHub run `check`, результат `deploy` (если выполнен),
состояние SSH/автозапуска/проверки с выключенным экраном, результат инвентаризации
и препятствия к продукту без Android framework, что осталось сделать.
Для ручного подключения дай команду с локальными путями к ключу и known_hosts, без содержимого
секретов. Не утверждай, что телефон доступен или inference работает, пока реальные проверки
не прошли. Полные логи с секретами и персональными идентификаторами в публичный repo не добавлять.
