# Задание локальному агенту: прямой SSH и подготовка минимальной системы Cerro

Доведи до рабочего состояния управление домашним Nubia Z60 Ultra
**NX721J / PQ83A01 / cerro**, репозиторий **qqrm/android_device_nubia_cerro**,
ветка **server-lite**. Пользователь потребовал убрать Tailscale. Используй обычный
OpenSSH в Termux по USB forwarding или домашней сети. Кнопка GitHub Actions
работает через домашний Linux runner с метками `self-hosted`, `linux`, `cerro-phone`;
локальный `phone.py` доступен и на Windows без runner.

Termux — подготовительный этап. Конечные SSH/inference-службы должны запускаться
без Android application framework; цель описана в [HEADLESS.md](../HEADLESS.md).
Сначала используй существующие ключи и проверь прямой SSH, затем удали прежнюю
сетевую интеграцию. Инвентаризация по USB не должна ждать настройки GitHub.

Прочитай `AGENTS.md`, [CONSOLE.md](CONSOLE.md), [DEPLOY.md](DEPLOY.md),
`bootstrap-ssh.sh` и `server/phone.py` в актуальной ветке. Выполняй доступные действия
самостоятельно. Если необходимы физическое подключение или подтверждение Android,
попроси только конкретное недостающее действие и продолжи после него.

## Порядок работы

1. Найди checkout или клонируй репозиторий, сохрани пользовательские изменения.
   Проверь `adb`, `ssh`, Python, `gh` и авторизованный доступ к нужному телефону.
   При нескольких устройствах выбери NX721J явно. Serial в отчёт не добавляй.

2. Через авторизованный USB ADB передай `server/device/inventory.sh` в
   `/data/local/tmp/cerro-inventory.sh` и выполни
   `adb -s SERIAL shell sh /data/local/tmp/cerro-inventory.sh`.
   Вывод сохрани приватно вне checkout. При ошибке сохрани частичный отчёт и отметь
   недоступные разделы; автоматически права не повышай. По `HEADLESS.md` выдели
   зависимости Wi-Fi, charging/thermal, power и storage. На этом шаге службы не отключай.

3. Проверь существующий Termux SSH-bootstrap и используй прежние deployment-ключ,
   SSH host key и доверенный `known_hosts`. Только если bootstrap не выполнялся,
   подготовь его по `DEPLOY.md`: ключ вне Git, на телефон только `.pub`,
   `openssh python` и запуск `bootstrap-ssh.sh` внутри Termux.
   Обычный ADB shell не может писать в private directory Termux от чужого UID.
   Не пересоздавай существующие ключи и не отключай host key verification.

4. Выполни `phone.py check` через USB по `CONSOLE.md`, затем проверь прямой LAN-IP
   телефона, если нужен Wi-Fi. Сохрани `HostKeyAlias=cerro-phone` и исходный host pin.
   Не пробрасывай внешний порт на роутере и не меняй сетевые настройки других устройств.

5. После успешного прямого SSH убери Tailscale именно с этого телефона:

   - Если ранее запускался скрипт проекта, проверь executable/cmdline процесса,
     указывающие в `~/.local/share/cerro-tailscale`. Останови только этот daemon;
     перед завершением процесса ещё раз проверь его PID и принадлежность.
   - Проверь пользовательские boot/supervisor hooks и отключи только те, которые
     запускают этот экземпляр. Затем удали его каталог состояния/бинарников,
     установленный `~/bin/cerro-tailnet.sh` и файл `~/cerro-tailnet-authkey`, если
     они существуют и подтверждено, что созданы по прежней инструкции проекта.
     Ключи и содержимое state/log не печатай.
   - Если на выбранном NX721J установлено Android-приложение Tailscale, проверь
     пакет и удали именно его. Требование пользователя разрешает удаление этого
     приложения; остальные приложения и сетевые подключения не затрагивай.
   - После удаления повтори прямой `phone.py check`. Не удаляй Tailscale с Windows
     или других устройств и не меняй общую сетевую политику. Удалённый доступ через
     закрываемый маршрут не используй для самого удаления.

6. Для GitHub-кнопки настрой отдельный домашний Linux runner по `DEPLOY.md`.
   В WSL сначала проверь SSH под пользователем runner из самой WSL: USB forward
   Windows не означает доступность `127.0.0.1:18022` внутри Linux.
   До готовности runner продолжай локальную работу через `phone.py`.
   Обычные PR/build jobs оставь hosted; домашнему runner не передавай чужой PR-код.

7. Через авторизованный `gh`/GitHub UI настрой environment `phone` только для
   `server-lite`: variables `PHONE_HOST`, `PHONE_USER`, необязательный `PHONE_PORT`;
   secrets `PHONE_SSH_KEY`, `PHONE_KNOWN_HOSTS`. Удали устаревшие environment variables
   `TS_CLIENT_ID`, `TS_AUDIENCE`, если они присутствуют. SSH-секреты сохрани.
   Credentials передавай напрямую из файлов в secret store, без вывода в чат/логи.
   Если runner online, запусти:

   ```sh
   gh workflow run deploy-phone.yml --ref server-lite --repo qqrm/android_device_nubia_cerro -f operation=check
   ```

   Найди именно созданный run и дождись его результата. Исправляй конкретные
   ошибки адреса/порта, прав ключа или host pin, сохраняя проверки доверия.

8. Если пользователь уже выбрал локальную GGUF-модель, скопируй её по pinned SSH
   в `~/cerro-server/models/model.gguf` и выполни `deploy` локально либо через workflow.
   Не скачивай модель произвольно. Если модели нет, успешный `check` завершает настройку
   доступа; inference отмечай как ещё не проверенный. Перед deployment освободи 8080
   от прежнего ADB/ручного сервера и проверь старый boot helper `10-cerro` по `DEPLOY.md`.
   Не убивай все процессы Termux и не удаляй неизвестные boot-скрипты.

9. Проверь SSH с погашенным экраном. Настрой Termux:Boot и фоновую работу Termux.
   Без отдельного согласования телефон не перезагружай. При разрешённом reboot-тесте
   проверь доступ до и после первой разблокировки. Автозапуск inference добавляй после
   успешного ручного deployment через штатный launcher, без второго процесса сервера.

## Границы и результат

Не прошивай устройство, не меняй загрузчик, SELinux и системные службы, не делай
factory reset и не удаляй остальные пользовательские приложения/данные.
Сохрани модель, API-ключ, SSH-ключи и доверенный host pin.

Верни краткий отчёт: результат прямого USB/LAN SSH, что реально удалено,
результат инвентаризации, состояние runner и ссылка на `check`, если он запускался,
итог deployment и проверки с выключенным экраном. Явно отметь невыполненные
аппаратные проверки. Для ручного подключения дай команду с локальными путями,
без содержимого секретов и device serial. CI не подменяет проверку на телефоне.
