# Консольный доступ по SSH: USB или домашняя сеть

Телефон запускает обычный OpenSSH в Termux на порту **8022**. Компьютер подключается
по USB forwarding либо напрямую по Wi-Fi. Для локального управления достаточно
`adb`, OpenSSH и Python; GitHub runner нужен только для запуска операций кнопкой в Actions.
Termux остаётся этапом подготовки [минимального нативного продукта](../HEADLESS.md).

## 1. Проверить существующий SSH через USB

Используй уже созданные deployment-ключ и доверенную строку host key
`cerro-phone ssh-ed25519 ...`. Если bootstrap ещё не выполнялся, сначала выполни
[подготовку телефона](DEPLOY.md#1-один-раз-подготовить-телефон).

На компьютере с авторизованным USB ADB выбери нужный NX721J. Из корня checkout:

```sh
adb -s SERIAL forward --no-rebind tcp:18022 tcp:8022
python server/phone.py --host 127.0.0.1 --port 18022 --user TERMUX_USER --ssh-key PRIVATE_KEY_FILE --known-hosts KNOWN_HOSTS_FILE check
```

Подставь serial, Termux username и локальные пути; пути с пробелами заключи в кавычки.
Команды подходят и для Windows с установленными Python и OpenSSH. Если forward уже
существует, проверь `adb forward --list` и используй только маршрут к этому телефону;
не переназначай занятый порт вслепую. `check` не требует GGUF-модели и не запускает inference.
Serial, ключи и полный диагностический вывод в публичный отчёт не добавляй.

`phone.py` проверяет закреплённый host key. При несовпадении ключа проверь устройство
и доверенный bootstrap-вывод; не отключай проверку и не пересоздавай ключи автоматически.
После окончания работы созданный forward можно убрать:

```sh
adb -s SERIAL forward --remove tcp:18022
```

## 2. Проверить прямой доступ по Wi-Fi

Подключи компьютер и телефон к доступной друг другу домашней сети. Возьми текущий
локальный IP телефона из его настроек Wi-Fi или используй локальное DNS-имя:

```sh
python server/phone.py --host PHONE_LAN_IP --port 8022 --user TERMUX_USER --ssh-key PRIVATE_KEY_FILE --known-hosts KNOWN_HOSTS_FILE check
```

Ключи и host pin остаются теми же. При отказе проверь адрес, SSH listener и изоляцию
клиентов/гостевой Wi-Fi. Для постоянной настройки можно закрепить локальный адрес
телефона в DHCP. Открывать SSH-порт на внешнем интерфейсе роутера не требуется.

## 3. Управление и GitHub Actions

С теми же параметрами подключения доступны `status`, `start`, `stop` и
`deploy --bundle LOCAL_VERIFIED_BUNDLE`. Подготовка модели, сборка набора и проверка
inference описаны в [DEPLOY.md](DEPLOY.md).

Workflow использует домашний Linux runner с метками `self-hosted`, `linux`,
`cerro-phone`. До его регистрации локальные команды работают самостоятельно;
GitHub-hosted runner не получает доступа к домашнему адресу.
Проверь `phone.py check` из той же среды и под тем же пользователем, где будет runner.
USB `127.0.0.1:18022` относится к среде, создавшей forward: Windows localhost
не следует автоматически считать localhost внутри WSL. Для WSL проще сначала
проверить прямой LAN-маршрут либо отдельно обеспечить USB forwarding в самой WSL.

Проверки с выключенным экраном и после согласованной перезагрузки выполняются
отдельно. Успешный CI не подтверждает доступность реального телефона.
