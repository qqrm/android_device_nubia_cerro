# Минимальный сервер для NX721J

Набор для Nubia Z60 Ultra: `llama-server`, `llama-bench` и управление через ADB.
Используется существующий Android с его драйверами, Wi-Fi, зарядкой и терморегулированием.
Это исходный вариант для замеров на CPU; Adreno/NPU пока не проверены. Веб-интерфейс отключён.

Для управления телефоном из GitHub Actions через домашний NAT используй
[Termux + Tailscale deployment](termux/DEPLOY.md). Ниже — прежний самостоятельный путь через ADB.

## 1. Собрать в GitHub Actions

1. Открой [Build minimal Android server](https://github.com/qqrm/android_device_nubia_cerro/actions/workflows/server-kit.yml).
2. Нажми **Run workflow**, выбери нужную ветку и запусти сборку.
   Кнопка доступна после появления workflow в ветке репозитория по умолчанию.
3. В успешном запуске скачай artifact **cerro-server-android-arm64-cpu** и распакуй ZIP.
4. Внутри находится `cerro-server-android-arm64-cpu.tar.gz`, его `.sha256`,
   `build-report.json` и `elf-report.txt`. Распакуй `.tar.gz`: получишь каталог `cerro-server/`.

Сборка использует закреплённые `llama.cpp` **b12177**
(`6c01da6278ab6c69ed67d9124806b50d2b299ba7`) и Android NDK **29.0.14206865**.
Версии закреплены в `server/versions.json` репозитория, состав результата — в `provenance.json`
и `SHA256SUMS`. AOSP и исходники ядра для этой сборки не скачиваются.
GGUF-модели и API-ключи в artifact не входят.

## 2. Подготовить телефон и компьютер

- На компьютере нужны Python **3.10+** и [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools).
  Команды ниже используют `python`; в Windows при необходимости замени его на `py`.
- На NX721J подключи Wi-Fi через штатные настройки, включи USB-отладку,
  подключи USB и подтверди доверие этому компьютеру на экране телефона.
  Набор собран для arm64 и Android **9 / API 28 или новее**.
- Скачай совместимую GGUF-модель отдельно. Для сравнения запусков сохраняй один и тот же
  файл модели, размер контекста и параметры нагрузки. Размер и лицензия модели зависят от выбранного файла.

## 3. Установить и проверить через ADB

В терминале компьютера перейди в распакованный `cerro-server/`:

```sh
python cerro.py verify --bundle .
python cerro.py deploy --bundle . --model /path/to/model.gguf
python cerro.py start
python cerro.py forward
python cerro.py probe
```

Для Windows подставь путь вида `C:\models\model.gguf`; пути с пробелами заключи в кавычки.
Если устройств несколько, укажи нужное: `python cerro.py --serial SERIAL start`.
`SERIAL` бери из локального `adb devices`; сохранять его в репозитории не нужно.

`deploy` устанавливает файлы в `/data/local/tmp/cerro-server` и создаёт случайный API-ключ
на компьютере: `%APPDATA%/cerro-server/api-key` в Windows, `~/.config/cerro-server/api-key` в Linux/macOS.
Свой ключ через `--key-file`: одна строка из 64 строчных hex-символов; в Linux/macOS права `0600`.
Сохрани ключ локально; при нестандартном пути передавай тот же `--key-file` команде `probe`.
Модель копируется как `models/model.gguf`, ключ — как `config/api-key`.

Сервер слушает **127.0.0.1:8080 на телефоне**, требует API-ключ для inference и запускается
с `--offline --no-ui`: модель берётся из локального файла. Начальные параметры:
CPU, 4 потока, контекст 2048, один параллельный запрос.
`forward` создаёт ADB-проброс на localhost компьютера; `probe` проверяет готовность,
отказ в inference без ключа и короткий запрос с ключом. Готовность сама по себе не заменяет inference-проверку.

```sh
python cerro.py status
python cerro.py stop
python cerro.py --help
```

Перед повторным `deploy` останови сервер командой `stop`. Лог запуска: `/data/local/tmp/cerro-server/server.log`.
При ошибке `.control-lock` сначала проверь отсутствие другой операции управления; автоматического снятия блокировки нет.
ADB-установка не настраивает автоматический запуск после перезагрузки.
После обычной перезагрузки снова подключи и авторизуй ADB, затем выполни `start`, `forward`, `probe`.

## 4. SSH и работа без USB

[Инструкция Termux](termux/README.md) описывает SSH с ключом на порту 8022,
туннель к локальному API и отдельную установку набора в домашний каталог Termux.
ADB shell и Termux работают под разными пользователями Android: Termux не получает
доступ к каталогу ADB-установки. Для автозапуска из Termux нужна собственная копия файлов.

## Проверка на телефоне: пока не выполнена

Успешная сборка в CI подтверждает сборку и программные проверки, но не работу на NX721J.
Перед выводами о пригодности постоянного сервера проверь на аппарате:

- SSH-вход по ключу и успешный inference с API-ключом при включённом и выключенном экране.
- Idle RAM и RAM под одной и той же нагрузкой; скорость, температуру и поведение при длительной работе.
- Сохранение Wi-Fi и восстановление сервера после перезагрузки; отдельно отметь, потребовалась ли разблокировка.
- Зарядку и доступность обычных настроек; используемые backend и параметры сохраняй вместе с результатами.

Отчёт CI и результаты устройства учитываются отдельно; ключи, модели, личные логи и идентификаторы хранятся вне Git.

Основа сборки: [официальная инструкция llama.cpp для Android](https://github.com/ggml-org/llama.cpp/blob/6c01da6278ab6c69ed67d9124806b50d2b299ba7/docs/android.md).
