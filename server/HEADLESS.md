# Цель: нативный сервер на Cerro

Конечная цель — отдельный минимальный серверный продукт для NX721J, который запускает
SSH и inference непосредственно как native services. Пользовательские Android-приложения,
лаунчер и телефонный интерфейс для этой роли не нужны. Termux используется на этапе
подготовки и проверки оборудования; его APK также зависит от Android framework.

**Сейчас готов native CPU kit для установленного Android. Готового образа без framework
и аппаратной проверки такой системы в этом репозитории пока нет.**

## Что оставить и что исключать

| Часть | Целевое состояние |
| --- | --- |
| Ядро, необходимые vendor-модули и firmware | Сохранить работающую основу устройства |
| UFS/файловые системы, USB, аварийный ADB | Сохранить |
| Wi-Fi, DHCP, DNS, время | Обеспечить нативное управление и восстановление сети |
| Зарядка, health, power и thermal | Сохранить управление и защиту под нагрузкой |
| Библиотеки Adreno/compute | Сохранить возможность проверки ускорения; текущий kit работает на CPU |
| Audio/vendor integration | Сохранить исходную интеграцию до проверки зависимостей на устройстве |
| SSH, inference | Запускать штатными native init services; управление по USB или домашней сети |
| Лаунчер, магазин, браузер, обычные APK, телефонный UI | Исключать из отдельного серверного продукта |
| Zygote, Java system services, ART | Цель — убрать зависимость от их выполнения; состав образа проверяется по зависимостям |
| Экран | Не обязателен для управления; небольшой статус можно добавить отдельно |

Нынешний `lineage_cerro.mk` наследует `full_base_telephony.mk` и
`common_full_phone.mk`. Поэтому добавление SSH в этот продукт само по себе не делает
прошивку минимальной. Нужен отдельный product с явным набором служб и пакетов.

В AOSP и используемой ветке Lineage есть `core_no_zygote.mk` с `ro.zygote=no_zygote`
и отключённой поддержкой Android-приложений. Это подходящая основа для исследования,
но её подключение не заменяет bring-up оборудования Cerro.

## Почему нельзя просто остановить system_server

Штатный Wi-Fi управляется Android system services через HAL. Для продукта без framework
нужно отдельно проверить запуск vendor-зависимостей, подключение к точке доступа,
получение адреса, DNS и переподключение. Сохранённый драйвер сам по себе этого не доказывает.

Аналогично, thermal HAL и ядро нужно рассматривать вместе с политикой управления
температурой и питанием. Не отключать эти службы ради уменьшения списка процессов.

Termux, Termux:Boot и текущий `phone.py` — инструменты этапа подготовки. В финальном
продукте SSH запускает `init`; deployment использует нативный/POSIX helper либо явно
включённый Python. Данные сервера должны быть доступны на предусмотренном этапе загрузки:
нельзя рассчитывать на обычный каталог Android-приложения, который может требовать
первой разблокировки после reboot. Это не требует отключать шифрование вслепую.

## Следующий аппаратный шаг

1. Выполнить read-only `server/device/inventory.sh` через уже авторизованный USB/ADB.
   Сохранить результат вне Git. Он фиксирует версии, boot-state, память, процессы,
   системные пакеты и состояния init-служб; он ничего не отключает. Этот шаг
   не должен ждать настройки сетевого доступа.
2. Подтвердить существующий SSH через USB forwarding.
3. Проверить [прямой SSH по домашней сети](termux/CONSOLE.md).
   Для управления из GitHub Actions использовать runner в этой же сети
   либо USB forwarding на компьютере runner; отдельный VPN не требуется.
4. По инвентаризации составить явный список необязательных компонентов и их зависимостей.
   Для пробного отключения нужен обратимый список действий и команд восстановления.
   Измерять память в одинаковых условиях, с тем же сервером и моделью.
5. Следуя `AGENTS.md`, проверить исходный аппаратный baseline, затем отдельный серверный
   product. Сборочную проверку отделять от проверки на настоящем NX721J.

Не считать `pm disable-user` удалением Android framework: оно может уменьшить набор
запущенных приложений, но не заменяет собственный минимальный продукт.
Не отключать Android framework на работающем телефоне до готовности нативных замен.
Прошивка, изменение загрузчика, сброс и перезагрузка для аппаратного теста остаются
отдельными действиями; скрипты этой стадии их не выполняют.

## Границы текущего решения

Готовый Linux/postmarketOS-порт именно NX721J здесь не подтверждён. Поддержка SM8650
в Linux ещё не доказывает поддержку платы телефона, её Wi-Fi, зарядки и GPU.
Уменьшение работающей системы также не означает автоматически маленький checkout
исходников или дешёвую полную сборку Android.
